# Message actions and failed-turn retry

Every persisted user and assistant bubble now has a three-dot disclosure beneath it. Delete message removes an assistant answer; Delete message and replies removes a user prompt, its linked answers and its conversation attempt references. Other turns remain untouched. Main-process admission rejects deletion during active operations. Repeated deletion is harmless. Immutable run records remain intact, while removed answers no longer participate in future model history. Recovery cannot resurrect deleted completed answers.

Enter and Send use the existing retry path when the latest attempt failed, was cancelled or was interrupted and the composer is empty or still contains that prompt. Edited text remains a new turn. The backend independently treats an identical latest failed prompt as a retry if a caller omits retryOf, preserving the original user message ID across repeated failures. Existing source identity checks still apply; this does not silently retry with changed evidence. Successful repeated questions remain new explicit turns.

Existing duplicate messages are not silently rewritten on read; users can remove them through the new menus. Conversation schemas remain unchanged. The optional additive deleteMessage IPC/preload method requires restarting Electron after the update; older bridges show a restart message. No historical run files are rewritten.

Verification: all 270 deterministic tests pass, including implicit repeated retries, successful recovery, edited prompts, answer/turn deletion, idempotency, immutable records and recovery. Production build/type checking pass. The isolated `scripts/electron-message-retry-smoke.cjs` passes repeated failed Enter submissions, empty Enter, reloaded Enter, explicit Retry, cancellation retry, independent edited prompts, answer deletion, turn deletion and persistence. `test-results/message-options.png` captures the menu; transport is synthetic, not live-model quality verification.
