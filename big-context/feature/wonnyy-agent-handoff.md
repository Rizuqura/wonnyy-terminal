## User workflow and ownership

- Context Boxes now participate in the existing Station Planet projection through `lib/context-box-stations.ts`. Each saved box has the same on/off filter control in the manager; Station **ANY** unions active collections and **ALL** intersects them, including combinations with legacy Stations. Review Station Context uses the combined matching paths for explicit review. Box membership/name edits update active filters; deleting a box removes its filter. No duplicate persisted Station is created, and visual filtering never rebinds a chat or grants source capabilities. Search navigation and vault changes clear box filters alongside legacy Station filters.
- Empty-text source regression: prompt validation now accepts a verified empty string alongside populated sources, preserving its envelope and source/hash provenance. Missing/non-string content still fails validation; an entirely empty box still produces deterministic insufficient evidence without inference. Backend coverage includes a mixed box and explicit retry after provider failure.

- The former right-panel Active Context / Build Package section is now **Context Box Manager** (`features/context-boxes/context-box-manager.tsx`). Reviewed context is the draft: it shows estimated source tokens, supports removal/clearing, and **Create Context Box** requests a name before saving. Saved boxes show current readable-source token estimates and open the shared details manager. Estimates are characters/4, not billed usage; prompt/history/output and CSV profiles affect actual model usage. Creating/cancelling this action never starts a chat. `node scripts/agent-electron-acceptance.cjs --context-manager` passed creation, token display, keyboard cancellation and details navigation; evidence is in `test-results/context-box-manager.json` and its screenshot.

- `features/context-boxes/context-boxes.tsx` provides the sidebar and HTML details/review dialogs, mounted by `components/app-shell.tsx` through `KnowledgeSidebar`. Explorer and Planet View feed the same selection. Saving preserves that selection.
- Select files/folders, choose **Add to Context Box…** or **Create Context Box from Selection…**, review the expanded list and choose/create a named destination. Files can be deselected. Unsupported/unavailable selections and duplicate memberships are disclosed. Names are trimmed, case-insensitively unique within the vault, and retain the existing 120-character limit.
- The sidebar `+` permits empty boxes. Details show source links, readability, estimates, rename, add selection, remove membership, manual relink and confirmed deletion. Removing membership or deleting a box never deletes source files. Paths are explicit vault-relative references; moved files are not guessed or silently reattached. Relinking preserves membership IDs.
- **Attach to Wonnyy Agent** preselects a box and opens/restores the panel. It does not create a chat, switch an existing chat or invoke a model. **+ New Chat** opens the preselected picker; **Create Chat** persists one **Untitled chat** using a creation ID. Cancel/Escape during setup writes nothing; controls/admission guards prevent duplicate submissions.
- A live chat's Context Box selector requires confirmation before switching future turns. Previously recorded answers keep their original sources and box labels. A preselected different box is visibly separate from the current binding. Missing/deleted boxes and empty/oversized collections have actionable explanations.
- `features/chat/use-chat-runtime.ts` retains shared renderer state, staged creation, per-vault restoration, streaming/cancel/retry, providers and searchable history. Active Context approval/save remains a compatible secondary entry point. Selection, global approval, panel opening and history browsing never create or rebind chats.

## Storage, migration and execution

- `.wonnyy/context-boxes.json` uses schema **2**: stable box ID, name, revision, timestamps and stable membership IDs with relative paths/added timestamps. Legacy `contextIdentity` is retained where present as historical metadata, not execution authority. Schema 1 boxes migrate in memory on read, then persist as schema 2 only on explicit mutation. Legacy membership IDs derive deterministically from existing source IDs and remain stable across reads/renames.
- New conversations use schema **3**, retaining IDs, creation IDs, storage locations and messages. Each attempt and assistant message has its own `contextIdentity`; confirmed switches record transitions. Schema 1/2 reads do not eagerly rewrite files. An explicit send/binding action carries forward old provenance before appending current-turn metadata. Unbound legacy chats require an explicitly selected box or a new bound chat. Pending-run recovery remains intact.
- Membership edits increment revision; rename changes only the label/timestamp. Folder contents expand during review only. Later files or Station matches never expand membership automatically. Deletion retains historical bindings and run records; further sends require an available box.
- `ChatService.boundScope` resolves membership in the active vault and reads latest source versions at request time. The orchestrator pins that turn's exact manifest and rechecks capabilities/hashes during controlled reads. Missing/unreadable/unsupported sources fail before inference, without fallback to global Active Context, Stations or universe. Empty boxes never fall through to universe scope.
- Per-turn hashes/manifests are retained, not full documents. Changes are signaled during preparation and in run diagnostics. Historical source links open current files; hash tooltips identify the version used. Model memory includes only exchanges matching the current source identity and box; other messages remain saved. Dataset memory is recomputed only for the verified identity.
- Existing `.wonnyy` paths, immutable run schemas, preload namespace, credentials, environment variables and provider adapters remain compatible. Atomic writes and serialized admission preserve prior storage on failure and permit explicit retry. Corrupt metadata is reported rather than overwritten. Legacy populated application-data fallback remains unchanged.

## Evidence and limits

The prompt identifies Wonnyy Agent and makes the selected box the only documentary evidence source. It separates source statements, inference, computed results and user-supplied calculation operands, and asks for an explicit selected-box insufficient-evidence answer. Structured citation IDs are validated against the request manifest. Existing CSV/statistics workers, PDF extraction and provider cancellation/retry remain in use. These checks do not guarantee semantic or factual correctness.

Chat supports 1–32 readable Markdown, CSV or text-PDF files per turn. Markdown/PDF prompt content retains the 80,000-character combined cap. CSV parses full allowed data in the worker and sends explicit profiles/results; samples are not complete evidence. Token estimates use UTF-8 bytes/3 plus framing, configured output allowance and 256-token reserve. Source/question budget checks run before model preparation or analytical planning. Oversize errors disclose available/estimated totals and per-file source estimates; sources are not silently truncated. Final/repair prompts are checked again. Sidebar estimates use approximate chars/4, separately labeled from assembled-prompt limits.

Scanned PDFs need existing extraction/OCR support; OCR and image interpretation are not added. Arbitrary snippets, external files, semantic retrieval, automatic move detection, web access, marketplace execution, drag/drop and box duplication are outside this implementation. Duplication was optional P1. Collection deletion, membership editing and explicit future-turn switching are implemented.

## Panel behavior

The floating panel retains eight pointer resize zones, pointer capture, keyboard arrow resizing, Home/Reset, viewport clamping, persisted geometry, separate header dragging, minimize and close/reopen. Preferred 360 × 360 minimums reduce in smaller viewports. Workspace retains its accessible width divider and Undock. The composer stays fixed while the timeline scrolls independently.
